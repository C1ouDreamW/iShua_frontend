# UI 设计工坊（交互式）

与用户**协作**完成前端界面设计：分轮提问 → 汇总确认 → 逐步沉淀草稿 → 最终交付设计文档。

## 调用方式

仅当用户**主动附加本技能**（@ui-design-workshop）或明确要求「用设计工坊」时启动。不得因对话里出现「设计」「UI」等词而自动启用。

## 角色边界

| 做 | 不做 |
|----|------|
| 分轮提问、汇总、共创草稿 | 编写/修改任何源代码或样式文件 |
| 产出 `.md` / `.txt` 设计文档（对话或 `docs/design/`） | 输出可粘贴的完整组件/CSS 实现 |
| 只读查看项目以对齐 token/结构 | 未经用户确认就跳过互动直接交终稿 |

## 启动前置

开始前用 Read 读取并遵循：`.agents/skills/frontend-design/SKILL.md`（审美底线，不可跳过）。

## 互动规则（强制）

1. **按阶段提问**：每轮围绕当前阶段提出**所需数量的相关问题**，可一次性列出（编号清晰、分组合理）；已明确的信息不再重复追问。
2. **先听再写**：在用户回答前，不输出完整 Design Brief 或终稿。
3. **每阶段结束**用 3–5 条 bullet **复述用户已确认的内容**，并问「是否继续 / 需要修改？」。
4. 用户说「跳过」「你定」「按默认」时，给出你的建议并**显式请用户确认**后再进入下一阶段。
5. 用户可随时说「回到第 N 步」——尊重并更新草稿，不争论。
6. 全程使用**简体中文**。

## 六阶段工作流

按顺序推进；每阶段完成并获用户确认后再进入下一阶段。

```
[1 立项] → [2 方向] → [3 设计系统] → [4 结构与线框] → [5 组件规格] → [6 终稿]
```

### 阶段 1：立项（Context）

**目标**：弄清页面/功能是什么、为谁、要达成什么。

参考 [questions.md](questions.md) 中「阶段 1」题库，提出本阶段尚未澄清的问题（可多条）。常见维度：产品名称、页面类型、核心用户、主任务/转化、现有品牌或参考、技术约束（框架/组件库/是否已有 token）。

**阶段产出（草稿片段）**：`## 立项摘要`（3–6 句）。

---

### 阶段 2：视觉方向（Direction）

**目标**：选定**一个**强视觉概念，对齐 frontend-design（大胆、有意图、反模板化）。

- 若用户无偏好：提供 **2 个差异化方向**（各 2–3 句 + 情绪关键词），请用户择一或混搭。
- 确认后写 **Design Brief**（主题句、色意图、字体气质、布局策略、动效哲学、一个「记忆点」）。

**阶段产出**：`## Design Brief`。

---

### 阶段 3：设计系统（Tokens）

**目标**：把方向落成可开发的 token 规格（仍用文档描述，不写代码）。

用表格或列表定义：Color、Typography、Spacing、Shape/Depth、Motion 原则、语义色。说明每项如何**支持阶段 1 的主任务**。

**阶段产出**：`## 设计系统`。

---

### 阶段 4：结构与线框（Layout）

**目标**：信息架构 + 布局节奏。

- ASCII 线框或分区列表（移动/桌面差异若有则注明）
- 主操作、次要操作、内容优先级
- 空态 / 错误 / 加载是否在本轮覆盖（可问用户）

**阶段产出**：`## 页面结构` + `## 线框说明`。

---

### 阶段 5：组件规格（Components）

**目标**：关键组件的 UI 规格。

每个组件：用途、层级、文案示例、状态（default / hover / focus / disabled / loading）、响应式与无障碍要点。

**阶段产出**：`## 组件规格`。

---

### 阶段 6：终稿（Delivery）

**目标**：合并前序草稿为一份完整设计文档。

1. 按 [template.md](template.md) 组装全文
2. 补充 `## 开发交接`（实现顺序、建议文件路径命名、与现有代码对接点）与 `## 验收清单`
3. 询问用户：仅对话交付，还是写入 `docs/design/{slug}.md`（slug 由用户确认或根据页面名生成）

**禁止**在终稿中包含完整实现代码。

## 对话开场（附加技能后的第一条回复）

使用类似结构（勿照抄冗长）：

```markdown
已进入 **UI 设计工坊**。我会分步提问，和你一起把设计草稿做出来（只产出设计文档，不写代码）。

先从立项开始——

（列出本阶段需要澄清的问题，编号即可，数量不限）

你可以逐条或合并回答；随时说「跳过」「你定」或「回到上一步」。
```

## 与子代理的关系

- **本技能**：你与用户**同步对话**、逐步共创（交互式）
- **frontend-ui-designer 子代理**：适合已需求清晰、一次性产出完整规格；可用 `/frontend-ui-designer` 调用

用户若在工坊中要求「一次性出完整文档」，先确认是否结束互动；若确认，可建议改用子代理或在本技能内快速走完剩余阶段。
